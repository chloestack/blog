전략을 취할 수 있도록 설계하는 것이 안정적인 에이전트를 만드는 핵심입니다.

### 적용 판단 기준

MCP 도입을 고려할 때 핵심 질문은 "이 도구를 하나 이상의 에이전트 또는 하나 이상의 LLM 공급사에서 재사용할 계획이 있는가"입니다. 답이 '예'라면 MCP 서버로 구현하는 것이 장기적으로 유지보수 비용을 낮춥니다. 팀이 분리되어 있거나 도구 배포 주기가 에이전트와 다른 경우도 마찬가지입니다. 반면 단일 에이전트·단일 공급사의 탐색적 프로토타입이라면 MCP 없이 시작해도 충분합니다.

> 핸들러 함수를 처음부터 순수 함수에 가깝게 작성해 두면, MCP 서버로 전환하는 비용은 데코레이터 몇 줄을 추가하는 수준으로 줄어듭니다.

에이전트 생태계가 빠르게 확장되는 현재 시점에서 MCP는 선택 사항이 아닌 기본 인프라에 가까워지고 있습니다. 프로토타입 단계에서 결합도 높은 도구 연동을 작성하더라도, 설계 원칙을 지켜 두면 언제든 MCP 서버로 자연스럽게 분리할 수 있습니다.
